# Permissions

**Declared, minimal, and justified** (P-38). The point is to ask the client once,
up front, for exactly what the loop needs — no more, so the grant stays
reviewable, and no less, so the loop does not stall overnight on a prompt nobody
is awake to answer.

**A permission the pipeline does not have is a stop, not a workaround** (P-39).
An agent that cannot run a command reports it. It does not find another route to
the same effect, because the other route is the one nobody reviewed.

> Generated by `/devteam:setup` from the charter's build, test and lint
> commands, then approved by the client. Regenerated whenever those change —
> and a regeneration that *widens* the set is shown as a diff, never applied
> quietly.

## Granted

| Permission | Why the loop needs it | Requested by |
|---|---|---|
| `Bash(<test command>:*)` | every verification re-runs it (P-19) | verifier, tester |
| `Bash(<build command>:*)` | a step is not done until it builds | implementer |
| `Bash(git status:*)`, `Bash(git diff:*)`, `Bash(git log:*)` | reading the tree state before and after work | all |
| `Bash(git add:*)`, `Bash(git commit:*)` | one commit per step; the commit is the unit of evidence | implementer, tester, documenter |
| `Read`, `Grep`, `Glob` | reading the project | all |
| `Edit`, `Write` | the work itself, bounded by the guard to declared scope (P-10) | implementer, tester, documenter |
| `WebSearch`, `WebFetch` | research digests from primary sources (P-36) | researcher |
| `Bash(rm devteam/*)` | **the manager only**, and only to remove an UNTRACKED file it created in error under `devteam/`. Granted because withholding it entirely has twice cost something concrete: a heartbeat that could not be retired, and a stray file that leaves `git status` non-empty and so fails the first precondition of every future verification. A file created in error and unremovable is a defect that compounds, and the alternatives — truncating, renaming — are the same effect by another route, which P-39 forbids | manager |

## Deliberately not requested

| Permission | Why not |
|---|---|
| `Bash(git push:*)` | publishing is outward-facing and `IRREVERSIBLE` (P-26). The client pushes, or answers a question first |
| `Bash(gh :*)` | the same, plus it can open, close and merge |
| `Bash(rm:*)` broadly, `Bash(sudo:*)` | destructive, and nothing in the loop needs them |
| package publication, deployment, anything that spends money | `IRREVERSIBLE` by definition |

## The escalation window

`<N>` hours. A `REVERSIBLE` question unanswered this long proceeds on its
recommendation and is recorded as `proceeded-unreviewed` (P-27). `IRREVERSIBLE`
and `CHARTER` questions ignore the window entirely and wait indefinitely.
