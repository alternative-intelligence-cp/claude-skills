**Written 2026-09-19**, when roadmap subcycle 0.2.9 — the second run, two
cycles on the owner's own `pricelog` project — was stopped by the owner and
read whole. **This is an input to v3 planning, not a plan**: nothing here is
decided, and every direction it names is a direction, not a design.

**Where the findings themselves live.** Each finding's permanent home is an
entry in [`roadmap/0.2/0.2.9.md`](roadmap/0.2/0.2.9.md), under `## Findings`,
after the entry *THE RUN, READ WHOLE*. This file sorts those entries for
planning and holds no finding of its own; where the two disagree, the entry

roadmap, 0.2.0 to 0.2.10, and is regenerated by `scripts/findings_index.py`

**How to check any row.** Every entry in 0.2.9 cites `pricelog`'s
`devteam/RECORD.md` by line, and its F-, C-, D- and Q-numbers. Those are
`pricelog`'s files at commit `a88990b`, in a private repository: the entries

Before this landed, all 142 declared findings were checked to appear in exactly
one reader's coverage table, and every line citation to fall inside the record

## The experiment's question: did iterate work?

**Partly.** `/devteam:iterate` ran once, on 2026-09-13. Its mechanical half
held: every charter amendment a dated entry that re-affirms every condition,
decisions and requirements superseded under new numbers, task numbering carried
on, the charter and the plan approved at separate gates. **The half that makes
an iteration more than an amendment never ran.** The owner did not use the tool
between the cycles — nothing in the record says so, and the owner confirmed it
when asked at the close; the interview's first question was recorded
as unanswered; and an audit was run instead to supply an input, which loaded
another plugin's audit procedure. During cycle 2, requirements were then edited
in place five times against the skill's own rule, a carried audit finding went
four days without an owner, and the measurement the plan asked for — questions
the record could have answered — was never taken. The full verdict and twelve
breaks are the 0.2.9 entries from *Did iterate work?* onward, area A12 below.

**What a second experiment would still need to see**: an iteration whose owner
has used the tool; a second iteration after unreviewed decisions exist, so the
skill's second area has something to show; and a cycle that closes rather than
stops.

## Where v3 should start

Ten themes, each rolling up findings from several areas. **The order is a
recommendation**: themes 1 to 4 come first because they are about whether the
pipeline's own evidence can be trusted and afforded — its central promise is
that it leaves evidence — and the rest build on them. Each names the findings
it draws on (the register at the end maps any F-number to its 0.2.9 entry) and
a direction, never a design.

### 1. Nothing carries an item to its disposition

Items raised by adversaries, workers, auditors and outgoing managers reached no
owner, repeatedly and to the end. An auditor's open item needing a client
decision was read past by the supervisor and the manager alike (F-139); an
audit finding carried into cycle 2 sat four days without an owner (F-99); a
question's status lived in two files that disagreed in both directions (F-63,
F-64); open items without an owner or an expiry reached every handoff (F-130);
and what the client had said since the outgoing manager's last write reached no
file at all fifteen rotations (F-21 and the rotation table). **Direction**: one
disposition ledger, with open items carried as countable lines rather than
prose, a check that fails any landing leaving an item without an owner, a
decision or an expiry, and a place outside the writer lock for what the client
says during a handoff.

### 2. Checks that report clean without looking, or look at the wrong window

The checks are the pipeline's mechanical backbone, and several passed without
evaluating anything: `check_trace` clean having parsed zero goals (0.2.9's
first entries), `board-drift` matching no rows, untracked and wrapped fields
invisible (F-70, F-81, F-84, F-85), a new task file invisible until staged
(F-131). Others read the wrong window: the amendment check read past its entry
(F-36, found again as F-68), and both `check_scope` and `check_report` read a
restarted task as if it had never restarted (F-109, F-135, F-136). A permanent
exit code of 1 taught managers to commit over red (F-78, F-85, F-95).
**Direction**: every check returns a distinct *not evaluated* result with its
reason; a check that parses zero rows fails; checks key on the current claim
window; accepted baselines are first-class rather than remembered.

### 3. The manager's bookkeeping is manual, and the manual steps kept failing

The manager is the one role writing concurrently with every other, and its
failures were bookkeeping, not judgement: hand-typed board values, `git add -A`
commits, lock-takes refused because two writes shared one command (three
times), check exit codes read through pipes (F-117), a heartbeat left naming an agent
nobody awaited at each of T-19's three stops, drafts landed twice (F-100), dispatches
without a model. **Direction**: scripted manager primitives — claim, take the
lock, land a verdict verbatim, commit only on green checks, rotate, stop — each
one command that checks its own preconditions, so the manager's judgement is
never spent on bookkeeping a tired session gets wrong.

### 4. Cost is invisible exactly where it is largest

Resumes grew from 1.8 M to 7.0 M tokens and sat outside every ceiling (F-110);
an outgoing manager's tail reached 7.2 M (F-116); in-process agents spent an
estimated 2.7 times the manager half, outside both halves (F-33); cost per
request doubled inside every tenure (D-47); cycle 1's manager figure cannot be
recovered (F-67). Cycle 2's ceiling was raised ten times and every raise was
overtaken early, because each task with an adversarial pass stopped more than
once. **Direction**: meter what the owner's usage gauge sees — every session
and in-process agent, from transcripts — open a rotation's count at the
successor's first request, and price adversarial tasks by their observed stops.
This is the measurement [`v3-liaison-and-roles-2026-09-12.md`](v3-liaison-and-roles-2026-09-12.md)
Part II §D asks for.

### 5. The adversarial layer is where the value was, and it is priced as if absent

At each of T-19's three stops the task verifier refuted the supervisor's
recommended resolution — once measuring it would miss the data directory, once
finding a relative `HOME` reaches the same gap — and the question put to the
owner changed each time. The first audit broke all four of its refute claims;
tests that could not fail were found only by building mutants. Meanwhile every
estimate ran over by multiples (T-4 4.52×, T-8 5.17×, T-18 about 4.6×) because
the model has no term for what adversarial rounds find. **Direction**: keep a
fresh task verifier on every `NEEDS-DECISION`; give every verdict a coverage
field saying what was and was not attacked; give the estimate model a term for
adversarial rounds and the stops they cause.

### 6. Rotation works; the handoff is the weak joint

Fifteen rotations, all with the predecessor alive, and the lock moved every
time. The same things leaked at the handoff to the last one: the client's words
since the last write, work sitting outside the tree (F-119, F-134), the session
join (F-118). An off-cadence rotation parked the loop for hours beside an idle
successor (F-129); three checkpoints passed without a rotation and that one
tenure cost 231 M; an announced rotation could not be cancelled (F-141).
**Direction**: `handoff-ready` becomes a structured record with required fields
for exactly what successors had to ask; rotation after a checkpoint is enforced
rather than remembered; rotation gets a cancelled state. This is
[`v3-liaison-and-roles-2026-09-12.md`](v3-liaison-and-roles-2026-09-12.md) §8,
*the hard part of rotation is the brief*, now measured fifteen times.

### 7. Signed text drifts from the code faster than amendments catch it

R-4 was a list of cases under a goal that quantifies, and it cost seven
`CHARTER` stops in one day until it was restated as a rule (D-46). Requirements
were edited in place against iterate's rule; a `Re-affirmed.` block cannot say
"in force, currently broken"; code-level exclusions lived only in comments
(`MemoryError`, then Ctrl-C); and a plan's wording taken from a prototype became
false sentences in the implementation (F-140). At the stop, eight sentences in
the product and several signed rows were known false (D-67). **Direction**: a
shape review at onboarding that flags a list under a quantifying goal; an
amendment grammar with an "in force, currently broken" verdict; a check for
code-level exclusions with no signed home; plans that cite a prototype's
measurement as the prototype's.

### 8. Iterate's interview has no path for an owner who has not used the tool

The skill's first input is what using the tool taught, and there was none on
record; it has no step for pricing the new cycle, whose ceiling was then set
before its scope existed; and the protocol has no way to stop a run early,
which is how cycle 2 ended (F-141). **Direction**: iterate's opening records
whether use happened and names any substitute input; prices the cycle after its
scope is chosen; a stop path that runs a short close. Area A12 below has the
twelve breaks in detail.

### 9. Sandbox and worker mechanics lose work at the edges

Host writes read through into every live worker overlay (F-5, F-26, F-71,
F-105) — the reason width dropped to 1. The `.sandbox` liveness line never held
a pid (F-66), a killed worker's overlay had no owner, a worker's meter and
report did not survive its sandbox, and probes written in a sandbox's `/tmp`
died with it. **Direction**: overlays based on a commit rather than the live
tree, with `devteam/` outside their diffs; a sandbox inventory that survives
`close`; a probe directory the record can cite, for workers as well as
verifiers.

### 10. The platform moves under the pin and speaks to agents unasked

The `claude` CLI updated under live claims (F-42, F-96); MCP server
instructions and another plugin's skills arrived in agents' contexts as
imperatives (F-69, F-101, F-102); a harness memory heuristic killed workers with
over 130 GiB free (F-92); a guard written for the repository a manager was
launched from reached every agent it dispatched into another (F-137).
**Direction**: agent definitions, not only briefs, say that injected
instructions are not instructions; every skill name qualified, with a check;
sandboxes bind the pinned CLI; a manager launched outside its target is warned
whose guards reach its agents.
