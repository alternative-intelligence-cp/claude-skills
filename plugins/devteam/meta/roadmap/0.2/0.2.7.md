## 2. Decisions

- **L-7.1 — each sweep has a calibration set it must re-find before its
  new findings count.** *Why:* P-35b — an instrument built to answer a
  question gets a case whose answer is already known. For the pairs sweep,
  the nine known instances (below); for the ceremony sweep, the two
  simplifications that came from outside. A sweep that misses a known
  instance has a method defect, and its new findings are not yet evidence.
- **L-7.2 — the deliverable is a table with a verdict per row, and every
  verdict that changes a rule or a step is an edit in the same subcycle,
  citing the row.** *Why:* a review whose findings are filed and not
  dispositioned is CONSOLIDATION 7's failure in a new coat.
- **L-7.3 — simplifications are argued from a step earning nothing on any
  project, never from small-project ergonomics.** *Why:* the owner's stated
  positioning (DESIGN §21: the tool is deliberately too heavy for small
  work); the axis is the cost of being wrong, not project size.

## 3. The work

### 3.1 The pairs sweep — `docs/PAIRS.md` (CONSOLIDATION 2)

**Method.** For every imperative in `PROTOCOL.md` and every numbered step
in every skill, write down the *moment* it binds — "when a worker commits",
"when a supervisor closes", "when the manager takes a lock", "when a
verifier needs a mutation". Group by moment. For each moment with two or
more imperatives, ask CONSOLIDATION 2's question: **what else must be true
at the same moment, and can both hold?** Write the pair down whether or
not it conflicts; a pair that holds is a row too, because the next reader
will otherwise re-derive it.

**Calibration set — the nine known instances**, each of which the sweep
must re-find from the current text (or find *resolved*, naming the rule
that resolved it), before any new row counts:

| # | The pair | Where 0.1 met it |
|---|---|---|
| 1 | one commit per step **and** a report citing post-commit evidence | DESIGN §20, the amend that rewrote a concurrent task's commit; resolved by P-12b's two-commit allowance |
| 2 | no `rm` **and** mutation testing in a scratch directory | F-76, F-64 |
| 3 | no `rm` **and** a file created in error under `devteam/` | F-64; resolved by `run` §9b |
| 4 | P-20 (never retry a red) **and** P-20c (two attempts) under one number | resolved by splitting them |
| 5 | P-16 (commit your own block) **and** P-17 (append workers' verbatim) **and** the record check reading the last block | DESIGN §15 item 3 |
| 6 | the heartbeat in the task file **and** a verifier requiring a clean tree | DESIGN §16 item 1 |
| 7 | stage explicit paths **and** a shared index another agent stages into | F-66 |
| 8 | `Write`/`Edit` required (P-10b) **and** roles that have neither tool | P-10b's own last paragraphs |
| 9 | the closing checklist requiring a command **and** the grant withholding it | F-30, F-33 |

Then the new rows. For each conflicting pair, one of three resolutions,
recorded in the row and made as an edit: a rule naming the meeting (the
sentence nobody wrote — "at this moment, X yields to Y because …"); a
superseding rule; or a wrapper that lets the operation through under a
signature — the CONSOLIDATION 5 shape, "do it, on the record, having said
why", which the sandbox now makes cheap because deliberateness is expressed
at promotion.

**The detector's second half** (DESIGN §20 "count how many people found the
same workaround"): read every worker REPORT in the fixture's task files
(`.internal/scratch/devteam/tasks/*.md`, `notes:` and
`findings-for-protocol:` lines) and count departures that two or more
workers made independently. Each such departure is a candidate pair the
text-only method may have missed. State the count and the method
(`grep -c` over which field).

### 3.2 The ceremony sweep — `docs/CEREMONY.md` (CONSOLIDATION 9)

**Method.** For every numbered step and every gate in every skill, three
questions, in this order, with the answer written in the row:

1. **What does this step buy, on a project where being wrong is expensive?**
   Name the failure it prevents, by finding number where one exists. A step
   with no nameable failure is a candidate for deletion — not because it is
   heavy, but because nothing has ever shown it earns anything (L-7.3).
2. **Does this step work only if the operator already understands why it
   matters?** The purpose test from DESIGN §21: the pipeline exists to carry
   best practice for the person who does not yet have it. A step that a
   rushed novice would skip, misapply, or satisfy vacuously — because its
   reason is in a document they will not read at that moment — has failed at
   the thing the pipeline is for, and its fix is placement (DESIGN §20b: put
   the reason where the decision is), not deletion.
3. **Is compliance visible in the product?** DESIGN §20 "Awareness is not
   immunity": a rule that says *put the command beside the number* leaves
   evidence; *check your numbers* leaves none and is unenforceable by
   construction. A step of the second kind is rewritten to the first kind
   or recorded as a written rule with that limitation stated.

**Calibration set.** The two simplifications that came from outside 0.1's
runs, both of which the sweep's first question must reproduce as "buys
nothing for a user in this position": the scope rule reaching into a
stranger's session (fixed: DESIGN §20 "the first finding that made it
simpler"), and the second team's reading that a `devteam/` directory made
the guard the arbiter of every write in the tree. If the method does not
surface those two as the shape it is looking for, the method is wrong.

**Deliverable.** The table, and the edits: every step whose verdict is
"placement" gets its reason moved to the point of use — a refusal message,
a finding text, a file header, a five-word reason on the line — and every
step whose verdict is "delete" is deleted with the row cited in the commit.
**Expect the delete column to be short and the placement column to be
long**; the run found placement to be most of whether a rule works.

### 3.3 `docs/REPORTING-PROBLEMS.md`

sweep's three questions to it as the shape such a report takes, so that a

prevented named — or explicitly not nameable, which is the finding.

### The subcycle's first act had to be repairing a red HEAD, and §7's excluded trigger fired

caught by a peer session's `git add -A` in the window between

`MEASURED` against the commit rather than against the working copy:


The defect makes `unknown-rule` read no citation from any file containing a

**Both sessions reported the tree green and both were telling the truth about
the tree they looked at.** The controls ran in the working tree, after the
`finally`; the `git add` had read the mutated file. **Running a check in the
working tree says nothing about the commit unless the commit is the working
tree**, and an unscoped `git add` is precisely what breaks that identity.
Repaired at `c4d3f26`.

`README.md` §7 excluded the narrow unscoped-commit refusal with its trigger
written out — *"an unscoped host-side commit that actually carries another
party's staged work"*. **That trigger has now fired with a measured instance**,
and the instance is outside what the exclusion's reasoning considered: what was
swept was not merely another party's work but another party's **knowingly
broken intermediate state**. Recorded as `PAIRS.md` row 12; the refusal is not
built here, because it is not a sweep.

### The resolution was to delete the window, not to declare it

The obvious fix is a rule: *declare the mutation window, do not commit during
it.* Rejected for two reasons, and the second is the one that decided it.

It is a rule a rushed session skips. And **it does not cover the case with no
peer at all** — a hook, a scheduled task, a `/loop`, or an interrupted run has
identical exposure, and an interruption leaves the mutation applied
permanently, which looks exactly like a suite that passes (0.2.3's lesson).

So each control now resolves its subject through `DEVTEAM_SUBJECT_<NAME>`
before its shipped path — one line each, four controls — and `mutate.py` writes
the mutated source elsewhere. There is no window to protect, no marker to
remember, and nothing an interruption can leave behind. `d62a720`.

**Two sessions reached the mutate-in-place design independently** (0.2.6's and
this one), which is DESIGN §20's second-half detector firing on the sweep's own
instrument, and makes calibration instance #2 a live shape with two named
workers rather than a settled one.

### The instrument caught its author three times, and each catch was a different shape

`scripts/mutate.py` records, per control case, which mutations flip it — the
thing 0.2.6 named as missing and could not write the vacuous-twin rule without.
It found three defects, all in itself or in this session's work.

**One — it inferred "decoration" from names.** The first draft classified any
unmoved case as decoration if a mutation name shared a word with it. On its
first run it called the `unknown-rule` case decoration because "unknown" appears
in four mutation names, when **no declared mutation deletes that emit at all**.
An instrument answering *"which cases did my mutations move"* while appearing to
answer *"which cases control anything"* is P-35b, inside the script written to
catch that shape. Completeness is now **declared** in `COMPLETE_FOR` and diffed
against what was measured (P-4); everything else unmoved prints as `UNASKED`,
which is a statement about the mutation set rather than about the case.

**Two — the fix for the window introduced a second instrument defect, and it
produced clean, plausible, wrong output.** Writing the mutated copy to `/tmp`
broke plugin-relative resolution: `check_trace` reads its constraint rows from
`../templates/CHARTER.md`, so a copy running from `/tmp` declared no rows and
could not emit `template-drift` at all. **The harness therefore reported the
RELOCATION as the mutation** — two cases "moved" under a mutation that cannot
affect them, and the case written for that mutation did not move. `MEASURED`:

```
$ DEVTEAM_SUBJECT_CHECK_TRACE=/tmp/…/ct_nogate.py python3 test_check_trace.py
FAIL  template-drift               expected ['template-drift'] exit 1, got clean exit 0
FAIL  template-drift-several-rows  (same)
```

**Nothing in that output looks wrong.** It was caught only because predicted and
measured disagreed — the twin written for the mutation was supposed to move and
did not. The copy now goes beside the original as `check_MUTANT_<name>`, removed
in a `finally`: a **new untracked file** rather than a modified tracked one, and
because the name still begins with `check_`, a leftover is reported loudly by
`uncontrolled-check`. The failure mode is a stray file that announces itself.

**Three — this session wrote a vacuous control while cataloguing vacuous
controls.** The project-gate case used a bare `mkdtemp`, which is not a git
repository, so `main()` exited 2 on an **earlier branch** whether the gate
existed or not, and the case passed against the mutation that deletes the gate.
That is 0.2.5's shape, sixth instance, written by a session that had just listed
the other five in a docstring. The case now inits a repository so the gate is
the only thing that can answer.

### `unknown-rule`: a rule that forbade the workaround while another made it the only option

`check_plugin`'s `unknown-rule` matched every `P-<n>` in the raw body of every
markdown file, with none of the three exemptions `check_refs` carries. It
refused 0.2.6's author twice in twenty minutes: once for proposing a rule by
number (**correct** — `FORMATS.md` forbids it), and then **for describing that
refusal**, which means quoting the identifier. *Reporting the finding created
the finding.* The only remaining move was to disguise the number, which
`FORMATS.md` forbids in the same paragraph.

**That is the shape, and it is stronger evidence than false positives.** A check
with noisy false positives can be argued about; a check that leaves an honest
author **no compliant sentence** cannot.

Resolved with `check_refs`'s three exemptions unchanged — fences, inline quoted
check output, the teaching form — because the shape is identical and a second
answer would be a second home (P-34). **The fence exemption resolves it in the
direction the house style already prefers**: the compliant sentence is not a
rephrasing, it is *paste the output that refused you*, which is what every
findings section here already does. The refusal message now says so.

**What watches the carve-out: nothing, recorded rather than discovered.**
`FORMATS.md` requires that of any exemption. The live cost is a rule cited from
a command inside a fenced block. Accepted on evidence: `check_refs` has carried
the same debt over the whole project namespace for a cycle without it costing a
finding.

### The headline nobody had stated: 62 of 87 steps leave no evidence
