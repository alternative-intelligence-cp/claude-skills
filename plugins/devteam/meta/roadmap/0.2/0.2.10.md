# 0.2.10 — the root-tree allowlist: a stray at the repository root is refused, not tidied — PLANNED

> The owner's stated pain: prior projects grew a root full of temporary
> scripts until the README sat pages down the GitHub file tree, and every
> clean-up meant stopping work. The `.gitignore` now keeps a root-level
> Python script off the remote (commit `322c895`) and says in its own
> comment what it does not do: stop one being created, or show it in
> `git status`. This subcycle is the mechanism: one declared list of what
> the root holds, a check that diffs the tree against it, and a hook that
> refuses the write at the moment it is typed.

## 1. Where you are

Independent of every other subcycle; needs nothing from the sandbox and
can be done at any point in the cycle. The repository root holds
(`MEASURED` 2026-09-05, `git ls-tree --name-only HEAD`): `.claude-plugin`,
`.gitignore`, `HANDOFF.md`, `LICENSE`, `README.md`, `plugins`. `.internal/`
exists on disk and is ignored.

Read: `scripts/check_plugin.py` — its `namespace-drift` finding is the
shape to copy: a table in a document diffed against a set the code holds,
both declared; `scripts/guard.py` `targets()` and `resolve()`, the
target resolver a hook reuses rather than re-implements; `.gitignore`'s
root comment; the root `README.md`; `skills/setup/SKILL.md` §3 for how a
hook is proved to fire rather than believed to.

## 2. Decisions

- **L-10.1 — the declared side is a table in the root README, and the
  check reads it.** *Why:* the README is what a visitor sees first, so the
  list of what the root holds belongs there regardless; and a list the
  check reads cannot drift from the tree silently. The README is the source
  of truth and the tree is what is checked against it — say which, or it is
  a spell-checker (DESIGN §20). *Declined:* an allowlist constant in the
  script (rule and check in one place); a dotfile at the root (one more
  root entry, read by nobody).
- **L-10.2 — the check reads what git would publish:** tracked top-level
  entries plus untracked entries git does not ignore. *Why:* the pain is
  the GitHub tree. An ignored stray is the `.gitignore`'s half and stays
  invisible here by construction; the two mechanisms are named side by side
  in the README table's caption so a reader knows which catches what.
- **L-10.3 — the check lives in `check_plugin.py`, not a new script.**
  *Why:* it already reaches the repository root for the marketplace
  manifest, and a new `check_*.py` would need its own control file for one
  finding pair. *Cost:* `check_plugin` is the plugin's self-check and this
  is the repository's; the finding text says so.
- **L-10.4 — the check first, the hook second.** *Why:* a check with an
  exit code is what a release step and CI can run; the hook needs a
  settings entry the operator applies (P-38's client/operator split holds
  for this repository too), and it is proved by a refused write, never by
  its control (`setup` §3).

## 3. The work

### 3.1 The root README's table

A section `## What is in this repository`: one row per top-level entry,
directories with a trailing slash, in the grammar `check_plugin` already
parses for the prefix table — `| \`README.md\` | this file |`. Its caption
carries the rule and both mechanisms: *everything at the root is listed
here; `check_plugin.py` reports an entry that is not; temporary scripts and
experiments go in `.internal/scratch/`, which is ignored; a Python file at
the root is ignored by `.gitignore` and so never reaches the remote.*

### 3.2 `check_plugin.py`: `stray-root-entry` and `stale-root-row`

- *documented* — the entries parsed from the README table
- *present* — `git -C <repo> ls-tree --name-only HEAD` plus the top-level
  component of every `??` line in `git status --porcelain -uall`; git has
  already excluded ignored entries (L-10.2)
- present − documented → `stray-root-entry <name>`, with the text a person
  standing at the root needs: *not listed in README.md's root table — a
  temporary file belongs in `.internal/scratch/`; a permanent one gets a
  row*
- documented − present → `stale-root-row <name>`
- both in the docstring's finding list, so 0.2.6's `docs/CHECKS.md` has
  their row: the rule is the caption sentence in 3.1
- `test_check_plugin.py` grows five cases on a throwaway repository built
  in the scratchpad, never on this one: a stray tracked file at the root →
  finding; a stray untracked, unignored file → finding; a stray untracked
  `.py` that the ignore rule covers → **clean** (the `.gitignore`'s half,
  and the false-positive twin); a table row for an entry not in the tree →
  `stale-root-row`; the real table against the real tree → clean

### 3.3 The hook — prevention

`scripts/root_guard.py`, beside `guard.py` and importing its `targets()`
and `resolve()`: a `PreToolUse` hook on `Bash|Write|Edit|NotebookEdit`
that refuses a write whose resolved target's parent is the repository root
and whose name is not in the README table, read at hook time — no second
list. Reads, `cd`, and every write below the root are untouched; a write
under `plugins/` is the plugin's own guard's business during a run and the
owner's otherwise. The refusal names `.internal/scratch/`, because
guidance belongs where the temptation is (DESIGN §20b).

Registered in `.claude/settings.json` at the repository root — a new root
entry, so it gets a row in 3.1 — which the operator applies. Control:
`test_root_guard.py`, discovered by `run_controls.py` by convention: a root
write refused, a `plugins/` write allowed, a `.internal/scratch/` write
allowed, a root read allowed, a target with an unexpanded variable not
judged (the guard's own stated limit, inherited and stated again).

### 3.4 Docs

`.gitignore`'s root comment gains one sentence naming the check and the
hook. Nothing in the plugin's README or DESIGN changes: this is the
repository's mechanism, not the pipeline's.

## 4. Verification

```
python3 plugins/devteam/scripts/check_plugin.py     → clean  [… and the line reports the root table's row count]
python3 plugins/devteam/scripts/run_controls.py     → all N controls green   (N = the previous count + 1)
touch stray.md && python3 plugins/devteam/scripts/check_plugin.py ; rm stray.md
                                                     → stray-root-entry  stray.md  …
```

Live, after the hook is registered and the session restarted: one `Write`
to a **literal absolute path** at the repository root that the table does
not list → refused, and the message names `.internal/scratch/`. Paste the
refusal under `## Findings`. A green control is evidence the script is
right, not that the hook is running.

## 5. Done when

- [ ] the README table exists and the check reads it; both findings and their five control cases exist
- [ ] `root_guard.py` and its control exist; the hook is registered; the live refusal is pasted
- [ ] the `.gitignore` comment names both mechanisms
- [ ] `check_plugin` and controls clean; cost in the title line

## 6. Do not

- do not put the allowlist in the script — the README is the source of truth, and two copies of it would be checked against each other rather than against the tree
- do not make the check read ignored entries; that half belongs to `.gitignore`, and a check that reports what the ignore rule already handles is a check that gets switched off
- do not extend the hook below the root, and do not register it inside the devteam plugin's `hooks.json` — that file loads into every project that installs the plugin, and this rule is this repository's
