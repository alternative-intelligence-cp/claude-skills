## 2. Decisions

- **L-6.1 — a check that cannot name its rule is withdrawn or its rule is
  written; never tuned.** *Why:* F-113 — its false positives are the
  missing rule showing up. Applied to three checks in 0.1 and it found all
  three proposing rules; the rest predate the test.
- **L-6.2 — before widening any grammar, run the widened rule over the
  fixture's corpus and read what it newly reports.** *Why:* DESIGN §20 "the
  detector needs a second half" — recognising `### S-n` as a declaration
  would have produced eleven `duplicate-id` findings; running it first is
  what said so. The corpus is `.internal/scratch/devteam/` (read-only).
- **L-6.3 — the amendment re-affirmation is a declared list diffed against
  a declared list.** *Why:* whether a decision made a done-means condition
  undischargeable is a semantic reading this project refuses everywhere;
  whether an amendment entry *enumerates* every DM-n and constraint row
  with a verdict is not.

## 3. The work

### 3.1 `docs/CHECKS.md` and `unruled-finding` (CONSOLIDATION 3)

One table, one row per class above: **finding → the rule whose two sides
it compares (P-n, or a `FORMATS.md` section, or a template comment) → the
two sides, named → verdict `enforces` / `proposes`.** Fill it by reading the
code, not the docstring; the docstring says what the author intended.

For every `proposes`: either write the rule (in `PROTOCOL.md` if it is
about the process, in `FORMATS.md` if it is about the grammar) with the
measured failure that justifies it, or withdraw the class — remove the
finding, its control cases, and record the withdrawal in the table with the
reason. **Expect to withdraw at least one**; a sweep that withdraws nothing
has not been adversarial.

Then `check_plugin.py` gains `unruled-finding`: the set of classes each
check declares (parsed from its docstring block — the convention is two
leading spaces and a hyphenated name, which is how this file's table was
produced) diffed against the rows of `docs/CHECKS.md`. Two declared lists.
Its control plants a class in a docstring that is absent from the table,
and the twin: a table row for a class no script emits (`stale-row`).

### 3.2 The audit namespace watched (CONSOLIDATION 7)

Per `FORMATS.md`, `COR-`, `SEC-`, `HYG-` are three-letter and therefore
invisible to `check_refs`. Make them declared, cited and checked:

1. **L-6.2 first.** Widen `check_refs`'s scanner to
   `[A-Z]{1,3}-<digits>` in a scratch copy and run it over the fixture's
   `devteam/`. Read every new line. Record the count and what they are
   under `## Findings` **before** changing the shipped script. This is the
   step that was skipped when the `F` namespace landed (F-63, F-64: a green
   tree became 62 `cited-undefined` at once).
2. Declarations: an audit finding is declared by `- **COR-6.** <one line>`
   in `devteam/audits/*.md` (the form the audit skill already prescribes).
   Reserve `COR`, `SEC`, `HYG`, `REV`, `CNV` in `FORMATS.md`'s table as
   *checked* three-letter prefixes; the paragraph "safe from collision also
   means unseen" is rewritten to say what now watches them and what is
   still carved out (nothing three-letter beyond those five).
3. `check_refs` resolves those citations in both directions
   (`cited-undefined`, `defined-uncited` apply as they do to `D-n`) —
   **and here `defined-uncited` is wrong for an audit finding**: a finding
   nobody cites is the normal state of a finding under `Disposition. open`.
   So the rule is: an audit finding must be cited *or* carry a `Disposition.`
   other than `open`; report `undispositioned-finding` for one with neither
   (this is CONSOLIDATION 7's check, stated so it passes L-6.1).
4. `open-finding-at-close`: in `check_trace` (it already reads task titles
   and statuses), a finding whose `Disposition.` is `open` and whose audit
   file names a task (from the filename `T-n-<dimension>-<date>.md`) whose
   title is `DONE` or `ACCEPTED`. Its control, and the twin: `routed T-m`
   with T-n closed → clean.
5. The existing control asserting three-letter prefixes need no reserving
   is now **inverted deliberately**: it asserts the five reserved ones are
   resolved and any other three-letter prefix is ignored. Record the
   inversion in the control's own comment with F-63's reason.

### 3.4 The estimate model, third revision

C-3 §4: ten of ten over, 1.78×, after two revisions that both moved the
per-unit figure and neither touched the shape. The overrun is on **rounds**
— steps run over steps planned (F-101, F-102). The model in `plan`
§"Order" and the guidance in `templates/tasks/TASK.md`'s `Estimate.` become:

```
tokens = steps × unit × (1 + r) + overhead
  unit     = per step-unit, measured: 440,000 at C-1's second revision  (cycle 0.1)
  r        = rounds rate, measured: 0.78 over ten tasks                  (cycle 0.1, C-3 §4)
  overhead = per task, measured: 150,000                                 (cycle 0.1, T-2's note)
```

with the rule that **`r` is corrected from the harness's measured budgets
at every checkpoint** (0.2.3 gives the numbers for free), and the sample
stated beside every constant. State also what the model still does not
capture: a task whose rounds come from a rule conflict rather than a defect
(the three worst overruns were that), which no estimate can price and which
0.2.7's sweep is for.
