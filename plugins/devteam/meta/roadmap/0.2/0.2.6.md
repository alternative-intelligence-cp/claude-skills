**The parser has a trap one level down, found by a peer session reviewing the
resolution rather than by the author.** Two shapes look like emit sites and are
not: the dispatcher's own definition
`add = lambda kind, where, detail: findings.append((kind, where, detail))`,
whose first argument is the parameter `kind`; and `set.add()` —
`seen.add(name)`, `discharged.add(r)` — an unrelated method sharing the name.
**A parser that silently skips any non-literal first argument handles both
correctly by accident**, and would also silently skip a genuine emit site
written with a computed name, blinding `unruled-finding` to exactly the class
most likely to need a rule. So the parser matches **bare `add(...)` only**,
excludes the lambda's own assignment, and **fails loudly on any surviving
non-literal rather than skipping it**. That assertion fires on nothing today,
which is the point: it is a tripwire, not a filter.

**57 per-file, 55 distinct.** `broken-link` is emitted by both `check_refs` and
`check_plugin`; `missing-field` by both `check_trace` and `check_report`. A
shared name is not a shared rule — `missing-field` in a task file and in a
report are different defects — so `docs/CHECKS.md` keys rows by
**(check, class)** rather than by class alone.

### Widening the scanner alone does nothing, and the reason defuses the obvious hazard

```
CITATION = re.compile(r"\b([A-Z]{1,2})-(\d+)\b")     # the regex
KNOWN    = {"G","DM","R","T","S","D","Q","C","F"}    # the gate
EXTERNAL = {"P"}
```

Widening `CITATION` to `[A-Z]{1,3}` over all 387 files reports **zero** new
findings, because an identifier whose prefix is in neither set is discarded
after matching. The prefix set is the gate; the regex width is not.

**That also disposes of the hazard this widening obviously raises.** `UTF-8`
matches `[A-Z]{3}-\d+` and occurs **639 times** in the corpus — as do `RFC-`,
`ISO-`, `SHA-` shapes generally. None becomes a finding, because `UTF` is not a
reserved prefix. The carve-out that makes three-letter prefixes invisible is the
same mechanism that makes them safe to widen to.

### The tripwire fired on its first run, against its author

The parser was specified to **fail loudly on a non-literal class name** rather
than skip it, because a silent skip would also skip a genuine emit site written
with a computed name — blinding `unruled-finding` to exactly the class most
likely to need a rule. Both this session and the peer that reviewed the design
predicted it would fire on nothing. **It fired immediately, twice:**

```
unruled-finding  scripts/check_report.py  check_report.py:200 emits a finding
                 whose class is not a string literal
unruled-finding  scripts/check_scope.py   check_scope.py:100  (same)
```

Neither was an emit site. `out.append((path, n, text))` in `check_report` and
`unparsed.append((rel, n, line))` in `check_scope` are ordinary list builds,
and the first draft of the parser accepted **any** `.append((tuple))`. The arm
is now bound to the list named `findings` specifically.

**The finding is not the bug; it is that the loud failure caught its own
author before it caught anything else.** A parser that skipped silently would
have been *correct on both files by accident* and would have shipped with the
defect intact.
