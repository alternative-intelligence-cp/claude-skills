**How the table is found: a deviation from L-2.1's wording, declared.** L-2.1
says `board-drift` reads the `## Tasks` table. It reads the table whose header
row names `Task` first and has a `State` column, wherever that table sits. The
control's own boards carry no `## Tasks` heading, and a board with the heading
renamed would otherwise go unread. The in-flight table's header ends in `Note`
and has no `State` column, so its rows are never read as Tasks rows. A row's
state is the cell under the `State` header, not the row's last cell
(`fp-the-state-column-is-found-by-its-header`).

**Choices made inside L-2.1 and L-2.2, each open to the owner's overruling:**
- **The vocabulary is matched whole.** A state with anything after it is
  `bad-board-state`, as a requirement or question status outside its set is

  several identifiers for the reason FORMATS gives there. `and` and `to` are
  not separators.

  only L-2.2 needs it. A row of it the grammar cannot read is then a part not
  evaluated, *BOARD.md's in-flight rows*, and the allowance fails closed on
