## 3. The work

### 3.1 Probe A — can a session start, message and replace another, with nobody at the keyboard?

**Why it can change the design.** L-2 decides the liaison on this probe.
0.2's L-8 rests on *a session cannot spawn its own interactive successor*, and
the cycle README's §4.6 found `claude --bg` on 2.1.281. If a session can start
its successor and hand over by message, rotation needs no owner at all —
whether or not a liaison is built — and 0.3.6 changes shape.

**What is known.** `MEASURED` 2026-09-23 from `claude --help`: `--bg,
--background` starts a session in the background and prints an id that
`claude attach`, `logs`, `stop` and `rm` take; `claude agents --json` lists
sessions with `cwd`, `kind`, `name`, `pid`, `sessionId`, `startedAt` and
`status`; `-n, --name` sets a session's display name; `-w, --worktree` creates
a git worktree for a session (so a worktree is **not** assumed to be the
default — check it); `--permission-mode` takes `acceptEdits`, `auto`,
`bypassPermissions`, `manual`, `dontAsk` or `plan`. Everything else is
`REASONED` until the steps below run.

**Setup.** `.internal/scratch/0.3.0/bg/` as a git repository with one commit.
Every step writes a marker file with a timestamp, so its result is on disk
rather than in anyone's context. Start every probe session with
`--model claude-sonnet-5` and a name `probe-a<n>`; the questions here are about
the harness, not the model.

- **A1 — start.** From a shell in the scratch repository:
  `claude --bg --name probe-a1 --model claude-sonnet-5 --permission-mode acceptEdits "Write the word ready to a1.txt, then list every skill you can invoke whose name begins devteam: into a1-skills.txt, and stop."`
  Record the id it prints; the `claude agents --json` entry for it, read three
  times — at once, while it works and after it stops — with each `status`
  value seen; `a1.txt`; `a1-skills.txt`, which says whether the devteam plugin
  loads in a background session; `claude logs <id>`'s last lines; and
  `git worktree list`, which says whether `--bg` made a worktree.
- **A2 — depth and waking.** Start `probe-a2` asking it to (a) dispatch an
  `Agent`-tool subagent that dispatches one more subagent, each writing
  `a2-depth<n>.txt` with its depth and the time; (b) run `sleep 60; date >
  a2-shell.txt` with `run_in_background`; and (c) write `a2-woke.txt` when that
  command's completion reaches it. Record which files exist and the gap between
  `a2-shell.txt` and `a2-woke.txt`. This is the manager's loop in miniature: a
  supervisor under it, and a wake on a background completion.
- **A3 — succession, which is the probe's centre.** Start `probe-a3s` asking it
  to start `probe-a3t` with `claude --bg`, send it a message, wait for the
  reply, write the reply to `a3.txt`, and then stop itself. Record whether each
  can see the other (`ListAgents`, and `claude agents --json`), whether the
  message and the reply both arrive, how long each takes, whether `probe-a3s`
  can stop itself, and the final state of both.
- **A4 — reaching the client.** Start `probe-a4` asking it to put one question
  to the user with `AskUserQuestion`, and to send a push notification first if
  it has a tool for one. Record its `status` while it waits and what `claude
  logs <id>` shows. Then ask the owner to run `claude attach <id>` in his own
  terminal, answer the question, and report whether a notification reached him
  and on which device. Record what he saw and how long the session waited.
  Then repeat once without the owner: `claude stop <id>` after five minutes, and
  record what the stopped session's transcript holds.
- **A5 — a permission it was not given.** Start `probe-a5` with
  `--permission-mode manual`, asking it to run one shell command. Record whether
  it blocks, what `status` says, and how the prompt could be answered.
- **A6 — what a rotation costs the starter.** From `probe-a3s`'s transcript,
  read its requests and processed tokens with `session_cost.py --transcript
  <path>` — pass the path directly, because the meter's own lookup fails for a
  project path containing a dot (the cycle README's §4.8). That is the
  backlog's *liaison tokens per rotation* (§6), measured once.

**The planted case.** Before A1, run the probe script with a fake `claude` on
`PATH` — a shell script in scratch that rejects `--bg` — and show that it
reports the capability as absent rather than passing.

**Afterwards.** `claude stop` and then `claude rm` every probe session, and
record that `claude agents --json` no longer lists them.

output here already reaches the user; a separate notification would be

and a later session recorded *"Remote Control disconnected — Session creation
failed"*. **Left unanswered**, the repeat stayed `waiting(input needed)` for
five minutes and was stopped. Its push notification was refused the same way.
The stopped transcript ends on the unanswered AskUserQuestion call: there is
no result and no row recording the stop, and `claude stop` keeps the
conversation so that `claude attach` can resume it.

**The four conditions, in the order they were met:**

1. **The directory must be trusted.** `claude --bg` exited `1` with *"Workspace
   not trusted. Run `claude` in …/bg once and accept the trust prompt, then
   retry."* No CLI command grants trust — `claude project` has only `purge` —
   and `-p` skips the trust dialog where `--bg` refuses. The owner ran `claude`
   there once. A devteam project is trusted when its client runs `setup` in it.
   A manager started in a project nobody has opened is not.
2. **A background session isolates itself, and writing in place is refused
   unless the project opts out.** Its system prompt has a
   `# Background Session` section, saved verbatim in scratch. The section tells
   the session to call EnterWorktree before any edit, and says edits in the
   shared checkout *"are rejected until you isolate"*. The first `probe-a1` did
   exactly that. A2 and A3 were rerun with the opt-out set in the scratch
   repository. Under the default, A2's subagent ran `git worktree add` and
   stalled the whole session on the prompt for it. A3's starter stopped to ask
   the user rather than route around the guard or run git it had been told was
   reserved.
3. **A background session commits, and pushes if there is a remote, unless
   told not to.** The same section says: *"commit before finishing — you don't
   need to ask — and push if the repository has a remote … Never push to
   main/master, force-push, or merge"*, unless the task, CLAUDE.md or memory
   reserves git. The first `probe-a1` was told only to write two files. It went
   on to `git add … && git commit … && git remote`.
4. **Any command outside the grant blocks the session, and nobody is told.**
   Three sessions stopped this way: A1's commit; A2's subagent's
   `git worktree add`; and a later A3 starter's `claude --bg … | tee
   a3-start.txt`. `tee` was not granted, and an earlier starter had used `>`
   for the same step. Each was listed `waiting` on a `permission prompt`, and
   nothing else anywhere showed it.

**Two readings the next subcycles must not make.** A session whose turn has
ended with a background task pending is listed `busy` until the task finishes.
The probe's first wake check read the listing, and it reported a false
`wake-unobserved`; the check now reads the transcript. And a stopped session is
listed at the checkout it started in, not the worktree it wrote in, so its
files are found only through every `cwd` it was listed at.

**Cost and cleanup.** Probe A spent **4,332,424 processed tokens over 94
requests, all on `claude-sonnet-5`, across 19 sessions and their subagents —
43.3 % of the owner's 10 M ceiling.** That is the probe's own meter, one row
per request id across every transcript; at the bundled reference's list
prices it is `$3.56`. It is above the `REASONED` expectation of 1 M to 3 M in
L-0.4, because the surprises cost two re-runs and 19 sessions rather than a
dozen. The ceiling covered it, which is what its size was for. Every
session was then stopped and removed with `claude stop` and `claude rm`, and
`claude agents --json --all` lists none. `rm` refused the first `probe-a1` while
its worktree held two uncommitted files — *"The worktree has uncommitted
changes. Deleting it would lose them."* — until those were deleted. And `rm`
leaves transcripts on disk: all 27, subagents included, were still there after
it, so probe B's meter still sees every probe session.

### 3.2 Probe B — what does the owner's gauge actually count?

**Why it can change the design.** L-7 makes the ceiling's instrument whatever
reconciles against the owner's `/usage`, and theme 4 says the current meters
see about a third of the spend. The model also changed under every anchor
(the cycle README's §8): Opus 5.5 lists 20% lower per token than Opus 5 and 60%
lower for cache reads. Whether the gauge follows list price decides both the
ceiling's unit and the answer to §10.4, model routing.

**What is known.** `MEASURED` 2026-09-23. A session's transcript is
`~/.claude/projects/<dir>/<session-id>.jsonl`, and each in-process subagent's
is `~/.claude/projects/<dir>/<session-id>/subagents/agent-<id>.jsonl`, with an
`agent-<id>.meta.json` beside it. `session_cost.py` reads only the session's own
file, keeps one usage row per request id (first row wins), and reports
processed tokens by model; it prices nothing. Run on the planning session it
read 73 requests and 21,176,140 processed tokens, all `claude-opus-5-5`.
Headless workers run with `--no-session-persistence` (`sandbox.py` dispatch), so
they leave no transcript, and their spend exists only in the sandbox's
`meta/budget.json` — which `close` deletes (F-9).

- **B1 — a meter over the whole machine.** In scratch, write a meter that, for
  a time window, sums every session and subagent transcript under
  `~/.claude/projects/`, found by globbing the directories rather than by
  computing their names; keeps one row per request id; and reports, by model
  and by project directory, the four token fields, processed tokens, and
  list-price dollars from a price table that is dated and cites the API
  reference bundled with the CLI. Measure two things before trusting it: whether
  a parent transcript also carries its subagents' usage rows, which would
  double-count them; and where probe A's background sessions wrote their
  transcripts. Worker spend is reported as **not metered**, with the reason
  above — never as zero (L-6).
- **B2 — reconciliation.** At least two intervals, each opened and closed by a
  whole `/usage` paste from the owner, and long enough that the all-model gauge
  moves at least five points; a day of his ordinary work is enough, and the
  probe spends nothing in the meantime. For each interval, record the change in
  the all-model gauge and in the Fable gauge, the metered processed tokens and
  list-price dollars by model family, and the ratios. Ask the owner whether he
  used Claude anywhere else in the interval — the web or the phone — because the
  gauge counts that and the meter cannot see it.
- **B3 — the answer.** Say which metered unit, if any, tracks the gauge with a
  stable ratio across the intervals, separately for Fable and for everything
  else; and what Opus 5.5 work costs in points against 0.2's Opus 5 anchors.
  If nothing is stable, say so plainly.

**The planted case.** Copy one finished transcript into scratch and compute its
totals with `session_cost.py --transcript`; B1's meter must reproduce them
exactly over a window that covers it. It must also find a session whose project
path contains a dot, which `session_cost.py` cannot.

**Observed.** **In progress — recorded before probe C starts (L-0.1).** Probe
B is passive, so its intervals run while C and D are worked.

- **B1 is built, and its planted case passed.** The meter is
  `.internal/scratch/0.3.0/meter/machine_meter.py`. Over a copy of the first
  `probe-a1`'s finished transcript, it reproduced
  `session_cost.py --transcript` exactly: 3 requests; 6 input, 1,171 output,
  58,185 cache read and 112,224 cache write tokens; 171,586 processed. Its
  list price for that transcript, `$0.472255`, equals the harness's own

- **Where probe A's sessions wrote.** Under
  `~/.claude/projects/<the cwd's name>/`, where `.` becomes `-` as well as `/`.
  For a session that isolated itself, that is the *worktree's* name.
  `claude rm` leaves transcripts on disk.

### 3.3 Probe C — a sandbox frozen at a commit (L-3)

**Why it can change the design.** L-3 decided *what* — each overlay's lower
layer is the commit a step starts from, and `devteam/` is read-only inside —
and this probe finds *how*, and what it costs, before 0.3.7 builds it. Today's
mechanism is `sandbox.py`'s overlay with `lowerdir` set to the host
repository's real path (its options string and mount, lines 584 to 606 as of
this writing), inside a bubblewrap plan that binds the merged view at the
host repository's own absolute path (lines 328 to 443).

**Setup.** `git clone --local ~/Workspace/REPOS/pricelog
.internal/scratch/0.3.0/overlay/host` — a real devteam project, cloned so that
nothing touches the original. Follow `sandbox.py`'s own two-stage composition
(`unshare` for the overlay, then `bwrap`), changing only what each step names.

- **C1 — a lower layer from a commit.** `git clone --local --no-checkout host
  lower && git -C lower checkout --detach <sha>` gives an independent
  repository at the base commit. Record its time and disk use, for the `host`
  clone and again for this repository, the larger case. Then try
  `git worktree add --detach` as the alternative and show whether a commit made
  in an overlay above it writes into the host's `.git/worktrees/` — the
  `REASONED` reason to reject it.
- **C2 — the planted case, first.** Open a sandbox over today's lower layer,
  the live host tree; write to the host's `devteam/RECORD.md` after the open;
  and show the write is visible inside. That is F-5 reproduced, and it proves
  the test can fail.
- **C3 — frozen.** The same sequence over C1's lower layer: the host write must
  not be visible inside.
- **C4 — read-only `devteam/`.** Inside, reading `CHARTER.md`,
  `REQUIREMENTS.md`, `DECISIONS.md` and a task file works — the four reads the
  `work` skill requires (the cycle README's §4.3) — and writing
  `devteam/tasks/T-1.md` fails. Record the mechanism that makes it fail (a
  read-only bind over the merged view's `devteam/`, or another), and the error
  a worker would see.
- **C5 — promotion onto a moved host.** Commit a product file inside, then
  commit something unrelated on the host, then promote through `sandbox.py`'s
  own path (bundle, fetch, cherry-pick). It must apply cleanly, and none of the
  promote gate's findings may fire spuriously.
- **C6 — width 2.** Two sandboxes at two different base commits, promoted in
  turn: both apply. Then a genuine conflict — both change the same line — must
  come back as `promote-conflict`, never as a silent merge.
- **C7 — the price.** The time and disk of one open, and whether several
  sandboxes can share one read-only lower layer per commit, each with its own
